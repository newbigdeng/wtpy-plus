# 怎样给工作台接入四类行情？

**临时看盘只收当前标的。长期留存另开采集进程。**

## 怎么选标的？

先选资产，再输入交易所代码。

| 页签 | 输入示例 | 网页读取什么 |
| --- | --- | --- |
| 股票 | `SSE.600000` | 腾讯证券的单股快照 |
| 期货 | `SHFE.rb2701` | 普通 CTP 的合约快照 |
| 期权 | `DCE.m2701-C-3000` | 普通 CTP 的商品期权快照 |
| 加密货币 | `BTC-USD` | Coinbase Exchange 的现货快照 |

期货页点「按需看盘」即可输入新合约。
期权页也可按标的期货查询本地合约链。
点击某个行权价后，才会连接行情前置。

股票和币对在上次请求结束五秒后再取价。
CTP 直接推送。切换标的会关闭旧会话。
隐藏标签页会暂停接收，回到页面会重新连接。
盘后请看源端行情时间。

## 看盘服务怎么启动？

股票和加密货币通过 HTTPS 取价。
若服务器无法直连 Coinbase，可设 `WT_CRYPTO_BROWSER=1`。
这样只有当前浏览器会请求所选交易对。
需要服务端出网时，可单独运行只读报价转发器。
`WT_COINBASE_RELAY` 指向其回环地址。
仅转发器持有代理配置。
期货和商品期权需要 CTP 行情 SDK。
默认使用 SimNow 交易时段前置。
休市联调时，可选「7×24 仿真回放」。
两个环境都显示源端交易日。
Linux 行情镜像还需生成厂商使用的中文字符环境。

```bash
# Debian 或 Ubuntu 已安装 locales 时
localedef --no-archive -i zh_CN -f GB18030 zh_CN.GB18030
```

```bash
python -m pip install openctp-ctp==6.7.11.0 QuantLib==1.39
```

可用 `WT_QUOTE_CTP_PYTHON` 指定独立解释器。
行情商另有前置时，设置 `WT_QUOTE_CTP_FRONT`。
需要登录时，在服务环境内设置以下变量。

```text
WT_QUOTE_CTP_BROKER
WT_QUOTE_CTP_USER
WT_QUOTE_CTP_PASSWORD
```

监控主程序已经注册资产接口。
已有监控服务也可旁挂独立进程。

```bash
python -m uvicorn wtpy.monitor.AssetServer:create_app --factory \
  --host 127.0.0.1 --port 8107
```

将 `/mgr/assets/` 转发到该进程，并关闭代理缓冲。
用 `WT_MONITOR_UPSTREAM` 指向原监控服务。
转发应保留 Host、Origin、Cookie 和公开只读标记。
新进程通过原服务检查账户会话。

## 长期订阅的数据放在哪里？

每类资产由自己的采集进程写入。

若某个行情源掉线，其他采集器仍可继续运行。
期货沿用原来的组合、采集器、策略库和回测目录。
新增工作区位于 `WT_ASSET_ROOT` 下。
该变量默认指向监控部署目录的 `assets` 子目录。

```text
assets/
  futures/quotes/       # 按需看期货时的临时会话
  stock/                # 股票
  option/               # 国内商品期权
  crypto/               # Coinbase 现货
```

| 每个工作区的子目录 | 用途 |
| --- | --- |
| `common/` | 合约、品种、时段、日历、费用 |
| `datahub/` | 采集器工作目录与行情配置 |
| `storage/` | 本资产的长期行情 |
| `quotes/` | 临时 CTP 会话，退出后释放 |
| `strategies/` | 本资产的策略源码与版本 |
| `backtests/` | 按账户保存的回测任务与结果 |
| `run/` | 独立模拟策略进程的工作目录 |

在 Linux 上用监控与采集服务共用的数据卷运行。
给每个采集进程明确列出要长期保留的合约。

```bash
export WT_ASSET_ROOT=/var/lib/wt/assets
python -m wtpy.monitor.AssetCollector option DCE.m2701-C-3000
python -m wtpy.monitor.AssetCollector stock SSE.600000 SZSE.000001
python -m wtpy.monitor.AssetCollector crypto BTC-USD ETH-USD
```

股票和期权复用 WT 数据中台的存储器。
它写入 Tick、分钟线，并按时段转储历史。
币对采集器将逐笔成交写入 `storage/matches.sqlite`。
按交易对和成交编号去重，按 UTC 时间聚合分钟线。

## 采集前要准备什么？

股票和期权分别准备自己的基础资料。

- 在 `common/` 放 `commodities.json`、`contracts.json`。
- 同处放 `sessions.json`、`holidays.json`、`fees.json`。
- 在 `datahub/` 放本资产的 `statemonitor.yaml`。
- 在 `datahub/feed.json` 放单个行情通道对象。

商品期权用 `ParserCTP`。股票采集用 `ParserXTP`。
`feed.json` 沿用对应 WT 通道的原有字段。
启动器按命令行合约设置订阅过滤器。
股票 XTP 行情权限由券商提供。

只看合约链时，可导入 OpenCTP 的公开合约字典。
文件只进 `option/reference/`，用于查找合约。

```bash
python -m wtpy.monitor.OptionChain instruments.json
```

用 CTP 合约加载器导出运行策略所需的基础资料。
保留标的期货、看涨看跌、行权价、到期日。
采集配置和凭据只放在本地数据卷。

币对采集器会读取交易所的价格和数量步长。
回测前，按自己的费用设置 `common/fees.json`。

## 如何回放或启动商品期权策略？

在「策略管理」选择期权，再保存策略版本。

打开期权回测页，选择该版本、数据集和日期。
选择分钟线时，CTA（趋势策略引擎）按闭合行情回放。
选择盘口 Tick 时，CTA 可按报价触达撮合。
点「查看结果」可读任务状态和收益摘要。

可从现有 SimNow 通道读取账户和认证信息。
将开平规则文件放在 `option/common/actpolicy.yaml`。
下面的第一条命令只校验所选合约和版本。
策略构造函数需接受 `name` 和 `code`。

```bash
python -m wtpy.monitor.CommodityOptionSim DCE.m2701-C-3000 Example 1 \
  --simnow-profile /run/simnow/td.yaml
```

该命令只校验配置。显式加 `--start` 才启动策略。
也可用 `WT_OPTION_SIM_PROFILE` 指定只读通道文件。
支持登记的交易时段第三前置和 7×24 仿真前置。
同一柜台账户下的策略共用资金和持仓。
成交、资金、持仓以该柜台回报为准。

## 调度中心怎样采集期权和币对？

各开一个采集进程，订阅列表和历史存储都分开。

1. 在调度中心打开「数据中台订阅」，选择资产。
2. 点已订阅期货查期权链，或点常用币对。
3. 将合约加入列表，再点「仅保存订阅」。
4. 点「启动采集」后，关掉网页仍继续采集。

部署时分别运行下面两个管理进程。
两者各挂载自己的资产目录，初始订阅为空。
只有币对采集进程读取 `WT_COINBASE_PROXY_FILE`。

```bash
python -m wtpy.monitor.CollectorControl option
python -m wtpy.monitor.CollectorControl crypto
```

管理进程报告的「运行中」表示采集进程已启动。
实际入库记录可到同资产的历史数据页查看。

## 怎样为不同期货中台选合约？

在调度列表点击期货中台所在行的「选择标的」。

- 页面按组合和通道环境读取清单。
- 选择合约后可预览新增和移除，再确认保存。
- 当前环境遵循交易引擎与采集进程的操作限制。
- 已停止的备用环境可预存下次启动使用的清单。
- 历史补数仍在监控中心的「行情数据」页。

要启用备用环境预存，将中台 ID 加入网页服务的
`WT_DEFERRED_HUBS`，多个 ID 用逗号分隔。
为每个 ID 单独建立共享目录
`assets/futures/deferred/<中台 ID>`。
网页服务与中台启动器必须能读写同一物理目录。
启动器在初始化行情引擎前读取清单。

```python
from pathlib import Path
from wtpy.monitor.DeferredSubscriptions import apply_at_start

apply_at_start(Path(shared_plan_dir), Path(datahub_dir))
```

若原订阅已经变化，启动器继续使用已有配置。
调度页显示原因，管理员可以重新选择。

## 怎样分析多个合约？

在合约链勾选要比较的期权，再点「开始分析」。

可以继续搜索其他品种和月份，保留已选合约。
服务用一条行情连接订阅这些期权和标的期货。
显示整条合约目录时不会自动订阅整条链。
关闭页面会释放行情会话和共享快照。

| 屏幕上的值 | 怎样读 |
| --- | --- |
| IV（隐含波动率） | 从期权与期货的双边中价反推 |
| Delta、Gamma | 期货价格变化时的斜率与曲率 |
| Theta | 期限减少一个日历日时的理论价格变化 |
| Vega、Rho | 波动率或年利率增加一个百分点的局部敏感度 |
| 试算敞口 | 每份合约按有符号手数和乘数折算 |

Theta 用期限缩短一天后的价格减去当前价格。
估值日期使用行情交易日，年分数按实际天数除以 365。
页面默认年利率为 2%，可按研究条件修改。
美式模型使用 QuantLib 的 BAW 提前行权近似。
Black‑76 给出欧洲式期货期权参考值。
报价无双边盘口、跨交易日或不同步时，该行不计算。

## 微笑、期限结构与价差怎么看？

先看同一月份的行权价，再比较不同月份。

- 微笑曲线展示同一标的、同一方向的盘口 IV。
- 平值 IV 取期货价格处的行权价插值。
- 看涨与看跌曲面分开，期限方向插值总方差。
- 曲面只覆盖各期限共有的行权价区间。
- 加权差对同执行价的看涨与看跌配对。

配对权重取双方较小的 Vega。图中记录每分钟的差值。
Z 分数只用此前已完成的分钟，最多取 60 个样本。
配对集合改变时重建历史，避免把换合约误当成信号。
10Δ 与 25Δ 按相同的绝对 Delta 比较两侧 IV。

跨品种估值使用 QuantLib 的 Kirk 引擎。
先选两份不同标的的期权，分别取其 IV。
再填写假设相关系数、单位换算倍数和价差行权价。
模拟标的是第一腿期货减去换算后的第二腿期货。
估值期限取所选合约的较早到期日。

## 策略怎样读取分析结果？

分析进程发布完整的一帧，策略按会话号读取。

Linux 进程对同一资产卷使用文件映射共享内存。
更新时替换完整映射。读取方一次只看到一个版本。
读取函数会检查会话环境及快照年龄。

```python
from wtpy.monitor.OptionFrames import read_option_frame

frame = read_option_frame(option_root, session_id, mode="simulation")
usable = [row for row in frame["rows"] if "iv" in row]
```

多合约回测在期权页选择主数据集和附加合约。
先在断网环境验证首根次周期行情的可见时间。
在 `WT_BACKTEST_RUNTIME` 指向的配置中指定原生库。
通过跨周期回放后才启用 `multi_period_replay`。
策略可从 `codes` 读取代码，从 `periods` 读取周期。
历史回测应在当时的行情上重算指标。

独立模拟运行用 `--also` 指定额外期权。
用 `--hedge-underlyings` 加入相应标的期货。
用 `--analysis-session` 把会话号传给策略。
这些参数只选择策略能读取的合约和数据。

## 怎样比较独立估价和盘口？

在分析页填「独立估值波动率」，再开始分析。

中价反推的 IV 描述市场报价。
独立估价使用你填的假设，不拿市场 IV 当答案。
两者使用同一标的价格、到期日和利率。

| 页面项目 | 怎样读 |
| --- | --- |
| 假设价格 − 卖一 | 买入时，估价比限价高多少 |
| 买一 − 假设价格 | 卖出时，限价比估价高多少 |
| 无有效双边报价 | 该行留空，不沿用旧估价 |

## 怎样回测一个期权组合？

在「在线回测 → 商品期权」选择已保存的策略版本。

- 选主期权，再加入其他期权或对应标的期货。
- 各腿选相同类型的数据，可混用一分钟和五分钟线。
- 点「使用共同区间」，查看到期前的共同交易日数。
- Tick 下的 CTA 策略可设置成交参与率与事件延迟。
- 手续费可沿用合约费表，或填写单边每手金额。

回测完成后，选交易日，点「读取历史风险」。
每个时间点按原生成交重建持仓，再按标的汇总。
分钟末只用当时可见的报价和已闭合的价格。
留空表示标的行情或有效期权估值缺失。

标的期货数据也应存于期权工作区。
例如分钟历史文件位于 `storage/his/min1/DCE/`。
同月份期权和标的期货使用各自的 DSB 文件。
只选静态期权池时，区间须在各腿到期前结束。
在静态回放中，各合约使用各自的持仓。
要跨到期日，打开同页的「跨到期日回测」。

## 怎样做一手买方仿真？

用独立容器运行买方工具，凭据只读挂载。

把期权专用目录挂到 `/option`。
把 SimNow 7×24 交易通道挂到 `/run/td.yaml`。
工作目录使用可写临时目录，用于柜台流文件。
同一账号不要同时运行其他交易程序。

下列命令只预览计划：

```bash
python -m wtpy.monitor.OptionBuyerSim DCE.m2701-C-3200 \
  --profile /run/td.yaml --root /option --premium-limit 1000
```

- 显式加 `--apply` 才做撤单、买开和卖平。
- 账户须空仓、无活动委托，开仓最多一手。
- 若撤单前已成交，这一手直接用于卖平。
- 改用 `--audit`，同交易日可只读复核。
- 每次都按柜台成交号、合约乘数和资金变化对账。

## 怎样把旧期权换成新期权？

先选两份豆粕期权，再指定移仓手数和日期。

例如持有两手旧合约，只移一手。
移仓日先平旧，再尝试开新。
若新合约没有开盘成交，旧仓不会恢复。
剩余旧仓持有到期，或按指定日期提前行权。

| 页面选择 | 怎么记账 |
| --- | --- |
| 首日开仓 | 按首个交易日开盘价模拟 |
| 原生 CTA 成交 | 接续所选任务的实际回测价格、手数和费用 |
| 到期前几个交易日 | 按样本交易日历倒数，不按自然日 |
| 主动行权或历史指派 | 在指定日按行权价建立对应期货仓 |
| 到期未被指派或主动放弃 | 释放对应期权仓位，不建期货仓 |

到期用标的期货当日结算价判断实值。
看涨买方行权得到多头期货，看跌买方得到空头。
卖方方向相反。平值和虚值默认失效。
若输入实际到期指派数量，剩余卖仓释放。
未提供配对记录时，默认实值卖仓全部被指派。

现金只计权利金、费用及期货盯市差额。
保证金冻结可用资金，不从现金再扣一次。
日终权益等于现金加期权持仓市值。
原生任务须在移仓日前完成所有旧合约成交。
清算结果单独保存，可在当前账户重新打开。

## 怎样取得跨期日线？

在期权工作区保存两个合约的逐日行情。

使用 `python -m wtpy.monitor.OptionExpiryHistory`。
传入 `--provider-config`、`--start` 和 `--end`。
最后传入新旧合约，如 `M2409-C-2900.DCE`。
`--output` 指向期权区 `history/expiry/样本名.json`。
样本名使用英文字母、数字、短横或下划线。

- Tushare 提供交易日历和合约到期日。
- 新浪提供逐合约日线和期货结算字段 `s`。
- 加 `--native-root` 可同时登记为原生回测日线。
- 原生选择框注明「历史导入」和样本名。
- 如果历史费表缺失，原生回测须填写每手费用。
- 取数命令在能读取凭据的环境单独执行。
- 若接口限流，稍后重试。已有样本不会覆盖。

## 卖方、多腿和到期怎样处理？

`OptionLifecycle` 使用同一个仿真通道。

先传 `--profile`、`--root` 和唯一的 `--ticket`。
再选动作。交易动作默认预览，显式加 `--apply` 才发送。

| 动作 | 使用方式 |
| --- | --- |
| `margin` | 输入权利金与期货价，查柜台成本 |
| `spread` | 买保护腿，再按实际成交量卖第二腿 |
| `snapshot` | 行权或到期前，保存期权和期货持仓 |
| `exercise`、`abandon` | 申报行权或放弃；行权先检查期货保证金 |
| `cancel-exercise` | 按柜台编号撤回仍待处理的申报 |
| `report` | 对照基线、行权回报、期货明细和结算单 |

价差只接同标的、同到期、同方向的两份期权。
输入保护腿、卖出腿、手数、资金预算和亏损限额。
还需传入包含两腿的 7×24 分析会话。
第二腿只按保护腿的已成交量发单。
未配对的多仓尝试限价卖平，剩余量会返回。
若委托终态未知，查柜台；不要盲目重发。

结算单与任务记录写在私有目录 `lifecycle/`。
用 `--baseline` 指定事前快照的记录名。
用 `--clearing-day` 指定核对的清算日。
申报获受理、执行成功、期货交割是不同的状态。

## 边界与不能说的结论


- 若采集器没运行，临时看盘不会补出历史 Tick。
- 币对逐笔成交没有买卖盘口，仅支持分钟线回放。
- 跨期日线按开盘价试算，不能还原盘口成交顺序。
- 费用和保证金率为输入值，不是历史柜台账单。
- 未填真实配对记录时，指派只是回测情景。
- 跨期结果不回写原生策略运行中的持仓。
- Kirk 估值与曲面差值不能证明多腿组合可以同时成交。
- 股票和币对看盘成功，不能证明交易柜台已接通。
