# 监控日志控制与文件读取修复

2026-10-15。本次改动只涉及监控与其原生前端，不修改策略、CTP接口或交易目标。

## 日志区现在怎样使用

日志区始终显示“自动刷新”与“刷新”。实时组合（`datmod=auto`）勾选后追加MQ日志，取消后暂停当前浏览器的追加；恢复后接收后续日志。历史组合（`datmod=mannual`）勾选后每15秒读取一次日志文件，取消后停止轮询。两种模式都可以手动读取Runner日志最近100行。

暂停不停止程序、行情、交易、落盘或成交通知；也不承诺补回所有历史MQ消息。选择按浏览器访问地址和组合ID保存在localStorage，不写入监控SQLite。存储被禁用时，当前开关仍可工作。

`monitor-log-controls.js`保留可读控制逻辑。上游只发布了编译JS，没有随包提供完整Vue工程，因此`tools/patch_monitor_log_controls.py`只维护少量挂接：显示原生复选框、调用控制器、阻止跨组合或过期HTTP响应覆盖日志、组件销毁后清理轮询并拒绝迟到响应。版本参数用于避免浏览器继续使用旧静态资源，没有新建另一套界面。

## 后端同步

- `DataMgr.get_channel_orders/get_channel_trades`在读完新增行后推进`lastrow`，反复刷新不再把两条记录追加成四条、六条。
- `WatchDog.applyAppConf`保存`schedule['active']`，不再把非空配置字典本身当作开启。
- `AppInfo.applyConf`切换MQ地址时为新接收器传`sink=self`，释放旧接收器后清空引用，避免消息无人接收或重复释放。

这些改动不改变Linux监控停止按钮的`kill -9`语义。JSON/CSV仍是表格的数据来源，点击资金刷新也没有新增直接查询柜台的接口。

## 定向验证

```bash
node tools/test_monitor_log_controls.cjs
python tools/patch_monitor_log_controls.py
```

维护脚本可在上游对应版本原始资源上使用，也可在已安装挂接的资源上再次执行；遇到未知上游片段会拒绝修改。不要把它用于其他版本的任意JS。

行为检查覆盖MQ暂停/恢复、手动模式单一定时器、按组偏好、存储失败降级、跨组/乱序回读，以及销毁后迟到响应不会重建定时器。从Git原版资源重做挂接，可逐字节重现部署文件；未做哈希校验。

实际浏览器使用无柜台的原生EventNotifier验收：A显示，暂停后B不追加，恢复后C显示，手动刷新补读B；切组仍记住暂停选择。历史两笔订单和成交连续读取三次均为`[2,2,2]`；独立临时非交易日期持仓样本在策略、组合和通道三种读取函数中均可读出1手，说明读文件没有交易时段门槛，不能证明柜台数据新鲜。调度false落库及恢复仍为false。

全程没有新增CTP订单或修改真实generated账本。部分原生页面日志/提示重复展示的来源仍未定位，不把这个遗留问题写成已修复。
